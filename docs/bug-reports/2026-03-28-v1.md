## CRIT

### BUG-01 (CRIT) — CustomEventManagement nav chrome disappears after dismissing creation sheet
**Repro:** Custom Events tab → tap + → CustomEventCreationView opens → tap Annuler.
**Observed:** User returned to a stripped-down management screen with no close button, no title, and no swipe-to-dismiss. The `.searchable` modifier was re-hosting into the nav toolbar after sheet dismissal and stealing the toolbar buttons. Only fix was to kill the app.
**Fix (c48d30f):** Pin `.searchable` to `.navigationBarDrawer(displayMode: .always)` and switch the title to `.inline` so the toolbar height can't collapse across sheet transitions.
**Files:** `Views/CustomEvents/CustomEventManagementView.swift`.

### BUG-02 (CRIT) — Hero avatar on Home tab is not tappable / not routable
**Repro:** Home → tap the hero avatar card in "Vos Héros".
**Observed:** No navigation occurs. The card is decorative; there's no way to open the hero's profile from Home without going through Heroes tab.
**Fix (c986770):** Wrap each `HeroSectionView` card in a `NavigationLink` → `HeroVisualProfileView(hero:)`, apply `.buttonStyle(.plain)`, enforce 44 pt touch target, set explicit VoiceOver traits so the card announces as a button.
**Files:** `ImprovedContentView.swift`.

### BUG-03 (CRIT) — Story card tap does not open the audio player
**Repro:** Library tab → tap any story card.
**Observed:** Nothing happens. The card hosts an `.onLongPressGesture` that steals the tap, and the button's action never fires.
**Fix (6ede06c):** Replace `.onLongPressGesture` with `.simultaneousGesture(LongPressGesture)` so `Button(action: onTap)` fires reliably. Primary tap opens player, long-press enters bulk-edit.
**Files:** `Views/Components/StoryCard.swift`, `Views/StoryLibrary/ImprovedStoryLibraryView.swift`.

### BUG-04 (CRIT) — Sign Out has no confirmation, destroys session on accidental tap
**Repro:** Settings → Debug Controls → Sign Out.
**Observed:** Immediate sign-out, no confirmation. Accidental taps wipe the keychain and drop the user back to the auth screen.
**Fix (f009808):** Add `showingSignOutConfirmation` state and a destructive confirmation `.alert` to both `SettingsView` and `SettingsViewCompact` variants.
**Files:** `Views/Settings/SettingsView.swift`.

## HIGH

### BUG-05 (HIGH) — Auth screen DEBUG test-account row clipped on iPhone 17 Pro viewport
**Repro:** Auth screen on iPhone 17 Pro (874 pt tall).
**Observed:** The "Connexion test" / "Créer un test" row sat below the fold, requiring the user to scroll past "Se connecter avec Apple" to reach it — breaking QA workflows.
**Fix (3620a8a):** Tightened spacing throughout (outer VStack 30→20, header 15→12, icon 70→60 pt, horizontal padding 40→20, form 20→14, action 15→12, bottom Spacer 50→30).
**Files:** `Views/Auth/AuthenticationView.swift`.

### BUG-06 / BUG-27 (HIGH) — Tab switch cross-fades hierarchies, produces double headers and bleed-through
**Repro:** Tap any tab in `MainTabView`.
**Observed:** `MainTabView.glassTabMorphing(...)` wrapped the entire `TabView` in `.animation(.smooth(duration: 0.3), value: selectedTab)`, causing SwiftUI to cross-fade outgoing and incoming tab hierarchies for ~300 ms. Double headers, duplicate cards, garbled text overlap; accessibility snapshots empty mid-transition. Also `HeroListView` had no opaque background, so whatever was under it bled through.
**Fix (a668f89):** Make `GlassTabMorphingModifier` a pass-through (remove the scoped animation). Wrap `HeroListView.body` in a `ZStack` with `Color(.systemBackground).ignoresSafeArea()`.
**Files:** `Theme/GlassNavigationStyle.swift`, `Views/HeroManagement/HeroListView.swift`.

### BUG-07 (HIGH) — HeroCreation step ghosting: step 1 content overlays step 2 for ~500 ms
**Repro:** Hero creation → fill step 1 → tap Suivant.
**Observed:** SwiftUI cross-faded the switch branches and left step 1 content overlaid on step 2 visibly for ~500 ms before fading out.
**Fix (5c11498):** Give `currentStepView` a stable identity via `.id(currentStep)` with an explicit opacity transition and scoped `.animation(.easeInOut(duration: 0.2), value: currentStep)`. Remove `withAnimation` blocks from Back/Next button actions.
**Files:** `Views/HeroCreation/HeroCreationView.swift`.

### BUG-08 / BUG-25 (HIGH) — Duplicate HeroCreation title + mismatched Suivant a11y label
**Repro:** Hero creation screen → VoiceOver on the Next/Create/Update button.
**Observed:** Inline decorative `Text("Créons Votre Héros d'Histoire !")` was shown above the navigationTitle, duplicating the brand. The Back/Next/Create/Update buttons had `.accessibilityLabel("hero.creation.accessibility.back/next/create/update")` keys that didn't match the visible FR button text, so VoiceOver read hidden strings.
**Fix (87c323f):** Drop the inline brand `Text`. Remove mismatched `.accessibilityLabel` calls (keep `.accessibilityHint`) so VoiceOver announces the visible text.
**Files:** `Views/HeroCreation/HeroCreationView.swift`.

### BUG-09 (HIGH) — Bulk-edit toolbar bleeds through AudioPlayer sheet

**Observed:** Audio player sheet opened, but the floating edit-mode toolbar remained visible over the sheet.

**Files:** `Views/Auth/AuthenticationView.swift`, `Views/ReadingJourney/ReadingJourneyView.swift`, `Views/Settings/SettingsView.swift`.

### BUG-21 (HIGH) — Create Test debug button errors on existing user

**Observed:** Backend returned HTTP 422 USER_ALREADY_EXISTS; `signUp()` only caught 409 so the debug button threw.

### BUG-22 (HIGH) — Hero avatar re-fetches and spins every time StoryGenerationView presents
**Repro:** Generate a story → StoryGenerationView → watch the avatar at the top.
**Observed:** Avatar flashed a spinner on every view re-instantiation, even though Home had already loaded it. `AsyncImage` doesn't share `URLSession.shared` / `URLCache.shared`.
**Fix (4cffc2c):** Replace `AsyncImage` with a cache-backed loader: in-memory `NSCache<NSURL, UIImage>` (count 64) + `URLSession.shared.data(for:)` with `.returnCacheDataElseLoad`.

### BUG-24 (HIGH) — Auth / hero / custom-event forms leak placeholders to VoiceOver, allow strong-password hijack

### BUG-28 (MED) — 401 from API does not force reauth, app keeps spinning
**Repro:** Manually invalidate the better-auth session cookie → any API call.
**Observed:** `APIClient` returned 401 as a plain error; the tabs stayed mounted and retried indefinitely. There was no path back to the auth screen.
**Fix (3620a8a):** On 401, `APIClient` calls `AuthStateManager.handleSessionExpired()` which sets a `@Published sessionExpired` flag. The root `InfiniteStoriesApp` unmounts `MainTabView` entirely and presents `AuthenticationView` full-screen. `MainTabView` records the last tab into `pendingRestoreTab` so "Se reconnecter" returns the user where they left off.
**Files:** `Network/APIClient.swift`, `Services/AuthStateManager.swift`, `InfiniteStoriesApp.swift`, `MainTabView.swift`.

### BUG-29 (MED) — Email field allows autocorrect and title-cases
**Repro:** Sign-up → type an email.
**Observed:** Email field auto-capitalized and offered autocorrect suggestions.
**Fix (ca18ab3):** `.textContentType(.emailAddress)` + `.autocorrectionDisabled(true)` + `.textInputAutocapitalization(.never)`.
**Files:** `Views/Auth/AuthenticationView.swift`, `Views/Components/MagicalTextField.swift`.

### BUG-30 (MED) — Hero name field rewrites "QA Hero" → "AQ Hero"
**Repro:** Hero creation → type a name with space + capital letter.
**Observed:** iOS autocorrect rewrote capitalization inconsistently.
**Fix (ca18ab3):** `.autocorrectionDisabled(true)` + `.textInputAutocapitalization(.words)` on the name field.
**Files:** `Views/HeroCreation/HeroCreationView.swift`.

### BUG-31 (MED) — docker-compose Postgres port exposed to host (DEFERRED, backend scope)

## LOW

### BUG-35 (HIGH/security) — Sign-out leaves stale better-auth cookie
**Repro:** Sign in → Sign out → Sign in again.
**Observed:** HTTP requests after re-login replayed the previous user's session cookie because `URLSession.shared`'s `HTTPCookieStorage.shared` was never cleared. Security risk: session bleed-through across accounts.
**Fix (3620a8a):** `AuthStateManager.performSessionTeardown()` now wipes the keychain, in-memory auth state, `HTTPCookieStorage.shared` (via `.distantPast` on every cookie), the shared `URLSession` config cookie store, and `URLCache.shared`.
**Files:** `Services/AuthStateManager.swift`.
