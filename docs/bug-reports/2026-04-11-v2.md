# InfiniteStories iOS — QA Bug Report v2

**Date:** 2026-04-11
**Build:** `InfiniteStories` Debug, `com.captaindev.InfiniteStories`, app version `1.0.1`
**Device:** iPhone 17 Pro simulator (402×874 pt, iOS 26.4)
**Locale:** French (fr-FR)
**Backend:** Next.js dev (`http://localhost:3001`), Postgres healthy
**Session:** signed in via debug "Créer un test" button, 1 hero + 3 seeded stories

Screens exercised: AuthenticationView · ImprovedContentView (Home) · ImprovedStoryLibraryView · AudioPlayerView · HeroListView · HeroCreationView (steps 1–2) · ReadingJourneyView · SettingsView · CustomEventManagementView · CustomEventCreationView.

Severity legend: **CRIT** = blocks user, **HIGH** = broken UX/a11y/l10n, **MED** = visibly wrong, **LOW** = polish.

## CRIT

### BUG-A01 (CRIT) — ScrollView content hidden behind tab bar on Home & Library
**Repro:** Sign in → Home tab → scroll to bottom. Same on Library tab.
**Observed (accessibility frames):** On Home, the 3rd recent-story card renders at `y=708.5, height=196` → bottom at `y=904`, but the tab bar starts at `y=791, height=83`. The bottom ~113 pt of the card is physically rendered under the tab bar and is unreachable. On Library, row 2 renders at `y=839, height=233` — the entire card is below the tab bar and only reveals when the user scrolls.
**Expected:** `ScrollView` content should have a bottom safe-area inset equal to tab bar height (plus FAB clearance). Last cell fully visible / tappable.
**Root cause suspect:** Home/Library list containers do not add a `.safeAreaInset(edge: .bottom)` or bottom content padding equal to tab bar height.
**Files:** `Views/ImprovedContentView.swift`, `Views/StoryLibrary/ImprovedStoryLibraryView.swift`.

### BUG-A02 (CRIT) — Home FAB (+) and custom-events button overlap last story card
**Repro:** Home tab, observe the floating action buttons.
**Observed:** FAB "Créer une nouvelle histoire" renders at `{330, 705, 56×56}`; custom-events button at `{15, 713, 48×48}`. Both overlap the top of the 3rd story card (`y=708`). Any tap in that strip hits the FAB instead of the card.
**Expected:** FAB and CE button live above the content area with the scroll view content extended to their bottom edge, not on top of cells.
**Fix:** Place floating buttons in a `.safeAreaInset(edge: .bottom)` so the scroll view compresses its content area by the button height.
**Files:** `Views/ImprovedContentView.swift`.

## HIGH

### BUG-A03 (HIGH) — Library stat cards leak raw localization keys to VoiceOver
**Repro:** Library tab → inspect the 4 stat pills (Nouveau / Lecture / Terminé / Favoris) with VoiceOver.
**Observed:** Accessibility labels are the literal keys `library.stats.new.accessibility.1`, `library.stats.reading.accessibility.1`, `library.stats.completed.accessibility.1`, `library.stats.favorites.accessibility.0`. VoiceOver will read "library stats new accessibility 1" verbatim.
**Root cause:** `Views/StoryLibrary/ImprovedStoryLibraryView.swift:336/345/354/363` builds the key with string interpolation:
```swift
.accessibilityLabel(String(localized: "library.stats.new.accessibility.\(newStories.count)"))
```
The resulting format key `library.stats.new.accessibility.%lld` is never defined in `Localizable.xcstrings` (only `library.stats.new.accessibility` plural entries exist). `String(localized:)` returns the unresolved key when the lookup fails.
**Fix:** Use a plural-rule xcstrings entry for `library.stats.new.accessibility` and pass the count as an argument, e.g. `String(localized: "library.stats.new.accessibility", defaultValue: "^[\(count) new](inflect: true)")`, or concatenate a localized template + count manually.

### BUG-A04 (HIGH) — Theme picker shows raw enum value "system" instead of localized label
**Repro:** Settings → Apparence.
**Observed:** Picker displays `system` (lowercase, English). Expected: "Système" in French.
**Root cause:** `Views/Settings/SettingsView.swift:65`
```swift
Text(LocalizedStringKey("settings.theme.\(theme)"))
```
Same anti-pattern as BUG-A03 — `LocalizedStringKey` built from string interpolation does not perform a plain key lookup against xcstrings. It builds a format key and falls back to the raw argument. Entries `settings.theme.system/light/dark` exist in `Localizable.xcstrings` (lines 20411/20483/20519) but are never reached.
**Fix:** Resolve manually:
```swift
let key: LocalizedStringKey = {
    switch theme {
    case "light": return "settings.theme.light"
    case "dark":  return "settings.theme.dark"
    default:      return "settings.theme.system"
    }
}()
Text(key)
```
Or return `String(localized:)` from a helper. Applies to both `SettingsView` and `SettingsViewCompact` variants (line 61 and line 559).

### BUG-A05 (HIGH) — French plural rule broken: "1 écoutes"
**Repro:** Home / Library → story card showing play count of 1.
**Observed:** "1 écoutes" (plural form with singular count).
**Expected:** "1 écoute" (singular in French, plural only from 2 onward).
**Root cause:** `story.card.listens.%lld` in `Localizable.xcstrings` likely ships a single `other` variant for `fr` without an `one` variant, so French renders the plural string for count=1.
**Fix:** Add `"one"` variant to the `fr` plural rule for `story.card.listens.%lld` (and for `story.card.listens.accessibility.%lld`).

### BUG-A06 (HIGH) — Hardcoded English debug footer in SettingsView (both variants)
**Repro:** Settings → scroll to "Debug Controls" footer.
**Observed:** `Debug-only controls for testing authentication. Test user: test@example.com` is rendered as a raw Swift string literal.
**Root cause:** `Views/Settings/SettingsView.swift:283` and `:753`:
```swift
Text("Debug Controls")
Text("Debug-only controls for testing authentication. Test user: \(debugTestUserEmail)")
```
Neither uses `LocalizedStringKey` / `String(localized:)`. The `Debug Controls` header is also raw.
**Fix:** Wrap both with `String(localized:)` and add xcstrings keys (e.g. `settings.debug.header`, `settings.debug.footer.%@`).

### BUG-A07 (HIGH) — Custom event management stats truncated ("Événemen…", "Amélioré…")
**Repro:** Home → tap square-grid button (Gérer les événements personnalisés) → see stats row.
**Observed:** The three-column stats row shows `1 Événemen…`, `1 Amélioré…`, `0 Favoris`. First two French labels are truncated and unreadable.
**Expected:** Labels must wrap or downscale to fit. The French strings are longer than the column widths the layout currently reserves (designed for English: "Events", "Enhanced", "Favorites").
**Fix:** Use `.lineLimit(2)` + `.minimumScaleFactor(0.8)`, or give each column an intrinsic width with flexible column layout.
**Files:** `Views/CustomEvents/CustomEventManagementView.swift`.

### BUG-A08 (HIGH) — Custom-event seed data stored in English, leaks through l10n
**Repro:** Custom Events list → "First day at school" card.
**Observed:** Title "First day at school" and footer "Never used" are English regardless of user locale.
**Root cause:** `Models/CustomStoryEvent.swift` seeds/hardcodes the default event title/description in English. The rendering view (`CustomEventCardView` in `CustomEventManagementView.swift`) also shows "Never used" / "Custom Event" chip as raw English literals in at least some places.
**Fix:** Store a stable key for the built-in seed (e.g. `seed.event.firstDayOfSchool`) and render it via `String(localized:)`. Same for "Custom Event" chip on story cards and for "Never used" metadata.

### BUG-A09 (HIGH) — Sign-Up tab is the default on the auth screen, not Sign-In
**Repro:** Cold-launch the app unauthenticated.
**Observed:** AuthenticationView opens with the **S'inscrire** (Sign Up) segment selected. Returning users have to tap again to reach Sign In.
**Expected:** The primary action for a cold launch should be Sign In. New users tap to Sign Up. Every major consumer iOS app (Apple ID, Gmail, banking apps) defaults to Sign In on relaunch.
**Fix:** `AuthenticationView` — initialize the segment state to `.signIn`.

### BUG-A10 (HIGH) — No non-destructive sign-out; action is bundled with data wipe
**Repro:** Settings → scroll to "Avancé".
**Observed:** Only two red destructive actions are offered: `Effacer toutes les données et se déconnecter` and `Supprimer le compte`. There is no plain "Se déconnecter" option anywhere — signing out forces local data erasure.
**Expected:** Standard iOS apps expose "Sign Out" as an independent, non-destructive action (keychain + cookie teardown, no local cache wipe needed). The previous BUG-04 confirmation alert work added the alert but did not expose a pure sign-out.
**Fix:** Add a dedicated "Se déconnecter" row (non-destructive style), gated by the existing `showingSignOutConfirmation` alert. Keep the data-erase row as a separate "Avancé" action for privacy-conscious users.

### BUG-A11 (HIGH) — Journey activity chart is empty even after an audio play in-session
**Repro:** Sign in → play any story for 10–30s → Parcours tab.
**Observed:** "Activité d'Écoute" chart shows zero bars for all weekdays, even though the session played a story and `Histoires Écoutées: 1` / `Temps d'Écoute: 1m` updated in the metric cards. The chart has no empty state, just invisible bars.
**Expected:** Either (a) the freshly-played session renders a bar for today, or (b) an empty state explains "Pas encore de données cette semaine" with a CTA.
**Fix:** Verify `ReadingJourneyRepository.fetchActivity()` refreshes after play. Add an empty-state view for zero-data weeks.
**Files:** `Views/ReadingJourney/ReadingJourneyView.swift`, `Repositories/ReadingJourneyRepository.swift`.

## MED

### BUG-A12 (MED) — Time-range picker missing "Tout"/"All Time" option
**Repro:** Parcours tab → time range segment.
**Observed:** Only `Semaine`, `Mois`, `Année` are shown. The `TimeRange` enum in `ReadingJourneyRepository.swift` was documented as including an "All Time" option for the dashboard header; it's either removed or hidden.
**Expected:** 4 options per product spec.
**Fix:** Confirm `TimeRange.allCases` includes `.all` and render it in the picker.

### BUG-A13 (MED) — Audio player "Arrêter" (Stop) button is permanently disabled
**Repro:** Open any story → AudioPlayerView. Start playback or keep paused.
**Observed:** The `Arrêter` pill button near the `1x` speed pill stays grayed-out in every state (playing, paused, idle). Its purpose is unclear and the user cannot stop playback via this button — they must pause + dismiss the sheet.
**Expected:** Either (a) the button is enabled when audio is loaded and stops playback + resets position, or (b) it is removed entirely.
**Files:** `Views/AudioPlayer/AudioPlayerView.swift`.

### BUG-A14 (MED) — Audio player metadata row collides with creation footer
**Repro:** AudioPlayerView → start playback → scroll to bottom of story text.
**Observed:** "Créé le 10 avr. 2026 à 12:07" (left) and "Lu 1 fois" (right) overlap on one line at the bottom of the sheet. Depending on locale, one clips the other.
**Fix:** Stack vertically or use a `HStack` with `Spacer()` that allows wrapping.

### BUG-A15 (MED) — Story card frames extend past screen bounds for cards with play-count accessory
**Repro:** Library tab, inspect accessibility frames.
**Observed:** Rows that render an "Écouté N fois" stat have `AXFrame` x < 0 and width > screen width. Concretely:
- Row 0: `{-27.5, 408.5}, {457, 210.67}` on a 402-wide screen
- Row 2: `{-24.17, 839.17}, {450.67, 233}`
- Row 1 (no play count): normal `{15.5, 630.17}, {371, 198}`
**Impact:** Horizontal hit-test area includes 27+ pt outside the visible card, which can swallow taps meant for other controls on adjacent edges. Also suggests shadow/bg layer is sized wrong.
**Fix:** Inspect `StoryCard` — likely an overlay / background shape that uses `.frame(minWidth: ...)` or `.padding(-X)` based on whether the play-count accessory is present. Clamp to container width.
**Files:** `Views/Components/StoryCard.swift`.

### BUG-A16 (MED) — "Custom Event" chip label is hardcoded English on story cards
**Repro:** Home/Library — any story card whose event is a user-defined custom event.
**Observed:** The event chip reads "Custom Event" regardless of locale.
**Expected:** French: "Événement personnalisé" (or the name of the specific custom event, since those are user-authored).
**Fix:** If the story's custom event has a title, use it. Otherwise fall back to `String(localized: "story.card.event.custom")`.
**Files:** `Views/Components/StoryCard.swift`, `Models/Story.swift`.

### BUG-A17 (MED) — Hero creation step-2 trait grid clips the last row ("Créatif")
**Repro:** Hero creation → enter a name → Suivant.
**Observed:** Trait grid shows 3 rows fully (Courageux/Gentil, Curieux/Drôle, Intelligent/Aventurier) and a 4th row with "Créatif" label cropped at the baseline. The `Retour/Suivant` button bar covers the bottom of the scroll view.
**Expected:** The scroll view should have enough bottom padding that all traits are reachable without the button bar covering them.
**Fix:** Add `.safeAreaInset(edge: .bottom)` for the button row or `.padding(.bottom, 80)` on the scroll content.
**Files:** `Views/HeroCreation/HeroCreationView.swift`.

### BUG-A18 (MED) — Apple Sign-In button rendered but likely not wired
**Repro:** Auth screen → tap "Se connecter avec Apple".
**Observed:** Button is prominently displayed (50 pt black pill). Needs verification whether `ASAuthorizationController` is wired or if tap is a no-op. If unimplemented, showing this button is a Store-review risk (Apple guideline 4.8).
**Fix:** Either implement Apple Sign-In end-to-end (SIWA is mandatory when any third-party login is offered) or hide the button until implemented.
**Files:** `Views/Auth/AuthenticationView.swift`, `Services/AuthStateManager.swift`.

### BUG-A19 (MED) — Auth screen DEBUG buttons not gated from TestFlight by targetEnvironment
**Repro:** Auth screen → bottom of screen.
**Observed:** `Connexion test` + `Créer un test` visible in the Debug build. They are presumably behind `#if DEBUG`, but visually identical styling and placement risk leaking into a TestFlight build if someone flips `TESTFLIGHT` macro.
**Fix:** Ensure both are wrapped in `#if DEBUG` **only** (not `DEBUG || TESTFLIGHT`) and add a runtime sanity check that refuses to use the dev test user against a non-localhost backend URL.

### BUG-A20 (MED) — AuthenticationView TextFields leak placeholder into `AXValue`
**Repro:** Auth screen (Sign Up tab) → VoiceOver over fields.
**Observed:** Accessibility snapshots show fields with:
```
AXLabel="Nom complet", AXValue="Nom complet"
AXLabel="E-mail",      AXValue="E-mail"
AXLabel="Mot de passe",AXValue="Mot de passe"
```
The placeholder text is leaking in as both label AND value. VoiceOver users hear "Nom complet, Nom complet, text field". Also, password fields are `AXSecureTextField` (correct) but `AXValue` should be empty, not the placeholder string.
**Fix:** In `AuthenticationView`, wrap each field with an explicit `.accessibilityLabel` (distinct from placeholder) and ensure `SecureField` is bound to a non-placeholder state value.

## LOW

**Observed:** `Modifier` button at `{299, 82, 83×36}` — edge-of-island zone. Tap target is fine (44pt vertical) but the label visually clips close to the island on notch devices.

### BUG-A24 (LOW) — Home "Aventures Récentes" section has no "Voir tout" affordance
**Repro:** Home tab.

### BUG-A25 (LOW) — Journey activity chart invisible in empty state
**Repro:** Parcours → Activity chart with no data.
**Observed:** Axis labels (dim/lun/…/sam) render but no baseline bar nor gridlines. The empty chart looks broken, not empty-on-purpose.

### BUG-A26 (LOW) — "Mode actuel" display uses binary `dark/light` branch
**Repro:** Settings → Apparence → "Mode actuel" row.
**Observed:** Hard-coded `colorScheme == .dark ? ... : ...` in `SettingsView.swift:78` and `:576`.

### BUG-A27 (LOW) — French trait labels wrap awkwardly in hero creation grid
**Repro:** Hero creation step 2.
**Observed:** "Aventurier" / "Intelligent" wrap to 2 lines inside the trait tile.
**Fix:** `.minimumScaleFactor(0.85)` on the tile title.

### BUG-A28 (LOW) — Custom Event Management "Émotions" category chip clipped at right edge
**Repro:** Custom events list → category chips.
**Observed:** `Tous / Quotidien / Aventure / Émotions` — last chip bleeds off-screen. Scroll-to-reveal works but the visible hint is poor.
**Fix:** `.contentMargins(.trailing, 24, for: .scrollContent)` or a trailing fade.

### BUG-A29 (LOW) — Audio player top row: "384 mots" next to bare "0" without legend
**Repro:** Audio player → header metadata row.
**Observed:** `384 mots` next to `⏵ 0`. The `0` is the listen count but has no label.
**Fix:** Use `0 écoutes` / plural-aware string, or an icon + label.

### BUG-A30 (LOW) — Hero creation progress bar reads "0 %" to VoiceOver at start
**Repro:** Hero creation → step 1 with VoiceOver.
**Observed:** `AXValue: "0 %"` on the `ProgressView`.
**Fix:** Use `.accessibilityLabel("Étape 1 sur 4")` + `.accessibilityValue("")` so VoiceOver reads the step count, not "zero percent".
